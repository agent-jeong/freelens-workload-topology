# 사용 가이드

---

## 1. 설치하기

1. [최신 릴리즈](https://github.com/agent-jeong/freelens-workload-topology/releases/latest)에서 `.tgz` 파일을 다운로드합니다.
2. FreeLens를 실행하고 **Extensions** 화면으로 이동합니다.
3. `.tgz` 파일을 드래그하거나 경로를 입력하여 설치합니다.

설치가 완료되면 클러스터 사이드바에 **Workload Topology** 메뉴가 나타납니다.

---

## 2. 처음 화면을 열었을 때

FreeLens에서 클러스터에 접속한 뒤, 사이드바의 **Workload Topology**를 클릭합니다.

화면은 크게 세 영역입니다.

**상단 툴바** — 네임스페이스 선택, 검색, 필터, Live 모드 등 조작 도구가 모여 있습니다.

**가운데 캔버스** — 리소스가 카드로 표시되고, 카드 사이의 선(Edge)이 연결 관계를 나타냅니다.
왼쪽부터 `Ingress → Service → Deployment → Pod → ConfigMap/Secret` 순서로 자동 배치됩니다.

**오른쪽 상세 패널** — 카드를 클릭하면 열리며, 리소스의 상세 정보를 확인할 수 있습니다.

---

### 카드 색상이 의미하는 것

- **초록** — 정상
- **노랑** — 주의 필요 (예: Pod 재시작 발생)
- **빨강** — 장애 (예: CrashLoopBackOff)
- **회색** — 상태 판단 불가

---

### 기본 조작

- **캔버스 이동**: 빈 곳을 드래그
- **확대/축소**: 마우스 휠, 또는 `-` / `+` 키
- **리소스 선택**: 카드 클릭
- **여러 개 선택**: `Shift` + 드래그
- **카드 재배치**: 카드를 드래그 (위치는 자동 저장됩니다)
- **위치 초기화**: 카드 선택 후 `Delete`, 또는 상단 **Reset layout**

---

## 3. 원하는 리소스 찾기

### 네임스페이스 변경

상단 툴바 왼쪽의 네임스페이스 드롭다운에서 선택합니다.
변경하면 해당 네임스페이스의 리소스만 표시됩니다.

### 이름으로 검색

`⌘K`를 누르고 리소스 이름이나 종류를 입력합니다.
일치하는 리소스가 캔버스에서 하이라이트됩니다.

### 레이블로 필터링

상단 툴바의 레이블 드롭다운에서 원하는 레이블을 선택합니다.
해당 레이블을 가진 리소스와 연결된 리소스만 남습니다.

### CronJob/Job 시간 필터

CronJob 드롭다운에서 **1h**, **24h**, **7d** 중 선택하면
해당 기간 내에 실행된 Job만 표시됩니다.

## 4. 리소스 상세 확인하기

카드를 클릭하면 오른쪽에 상세 패널이 열립니다. 패널 왼쪽 가장자리를 드래그하면 크기를 조절할 수 있습니다.

### Inspect 탭

리소스 요약 정보입니다.
Pod라면 노드, IP, 이미지, 재시작 횟수를, Deployment라면 레플리카 수를, Service라면 포트 매핑을 보여줍니다.
공통으로 레이블, 생성 시간, 소유자 체인이 표시됩니다.

### JSON 탭

전체 JSON을 트리로 탐색합니다.
키 옆 화살표로 펼치고 접을 수 있고, 값을 클릭하면 클립보드에 복사됩니다.
상단 검색창으로 원하는 키나 값을 찾을 수 있습니다.
Secret의 data 필드는 자동으로 마스킹됩니다.

### YAML 탭

YAML을 직접 편집하고 클러스터에 적용할 수 있습니다.

1. 에디터에서 값을 수정합니다. 변경 부분이 diff로 표시됩니다.
2. **Apply**를 클릭합니다.
3. 경고를 확인하고 적용합니다.

> `status`, `managedFields`는 자동 제거됩니다.
> `kind`, `name`, `namespace` 등 불변 필드는 변경할 수 없습니다.

### Events 탭

해당 리소스의 Kubernetes Events를 시간순으로 보여줍니다.
Normal/Warning 타입 배지, 반복 횟수, 발생 소스와 시간이 표시됩니다.

## 5. Pod 로그 보기

### 로그 열기

- 카드를 **우클릭** → **Pod Logs**
- 또는 카드 클릭 후 상세 패널의 로그 버튼

Pod 그룹이면 전체 Pod의 로그를 한 번에 볼 수 있습니다 (최대 24개).

---

### 검색 칩으로 로그 필터링하기

로그 검색의 핵심 기능입니다. 일반 검색과 달리 여러 조건을 조합할 수 있습니다.

**칩 만들기** — 검색창에 키워드를 입력하고 `Enter`를 누릅니다.

**여러 조건 AND** — 칩을 여러 개 만들면 **모든 키워드가 포함된** 라인만 표시됩니다.

> `[error]` `[database]` → "error"와 "database"가 둘 다 있는 라인

**OR 조건** — 칩을 클릭 → **+ OR condition** → 키워드 추가.
한 칩 안의 키워드는 **하나라도 포함되면** 표시됩니다.

> `[error, warn]` → "error" 또는 "warn"이 있는 라인

**제외 필터** — 칩을 클릭 → **Exclude**. 칩이 빨간색으로 변하며 해당 키워드가 있는 라인이 숨겨집니다.

> `[health-check]` (빨간색) → health-check 로그 숨김

**칩 관리**
- 클릭 → **Disable**: 삭제 없이 일시 비활성화
- 클릭 → **Delete**: 삭제
- 입력창 비어있을 때 `Backspace`: 마지막 칩 삭제

---

### 추가 필터

**Pod 필터** — 드롭다운에서 특정 Pod만 선택

**컨테이너 필터** — 사이드카, init 컨테이너 등 특정 컨테이너만 선택

**심각도 필터** — error, warning, info, debug, trace, unknown 중 선택
(로그 내용에서 자동 감지됩니다)

**시간 범위** — From/To로 특정 시간대만 조회.
**Earliest**/**Latest** 버튼으로 빠르게 끝점을 설정할 수 있습니다.

---

### 로그 탐색 팁

- **매치 이동**: `↑` / `↓` 키로 검색 결과 사이를 이동
- **실시간 추적**: **Live** 버튼으로 새 로그가 들어올 때 자동 스크롤
- **이전 재시작 로그**: **Previous** 버튼으로 컨테이너 재시작 전 로그 확인
- **더 불러오기**: Tail 수를 늘리거나 **Load Older**로 이전 로그 추가 로딩
- **줄바꿈**: **Wrap** 버튼으로 긴 로그의 줄바꿈 토글
- **특정 라인 숨기기**: 라인 우클릭 → Hide (숨긴 라인은 나중에 복원 가능)
- **다운로드**: **Download** 버튼으로 필터링된 로그를 `.txt`로 저장

## 6. 문제를 찾고 싶을 때

### Problems Only 모드

`⌘P`를 누르면 warning/danger 리소스와 연결된 리소스만 남고 나머지는 숨겨집니다.
정상 리소스 없이 문제에만 집중할 수 있습니다.

### 이슈 패널

화면 왼쪽에 문제 리소스 목록이 자동으로 나타납니다.
항목을 클릭하면 해당 리소스로 캔버스가 이동하고, 마우스를 올리면 상세 정보가 표시됩니다.

### Blast Radius

문제 리소스를 클릭하면 연결된 모든 리소스가 함께 하이라이트됩니다.
이를 통해 하나의 장애가 어디까지 영향을 미치는지 한눈에 파악할 수 있습니다.

### AI 분석

리소스를 우클릭 → **AI Prompt 복사**를 선택하면
리소스 정보, 이벤트, 상태가 분석용 프롬프트로 클립보드에 복사됩니다.
Claude, ChatGPT 등에 붙여넣어 원인 분석을 요청할 수 있습니다.

> Secret, 토큰, 비밀번호 등은 자동 마스킹됩니다. 외부 API 호출은 없습니다.

## 7. 실시간 모니터링

### Live 모드

`⌘L` 또는 상단 **Live** 버튼을 클릭하면 4초마다 자동 새로고침됩니다.
리소스 상태가 변경되면 토스트 알림이 나타납니다 (예: "pod-abc: healthy → warning").

### CPU/메모리 메트릭

클러스터에 [metrics-server](https://github.com/kubernetes-sigs/metrics-server)가 설치되어 있으면
Pod 카드에 CPU/메모리 게이지가 표시됩니다.

metrics-server가 없어도 토폴로지는 정상 동작합니다.
메트릭 오류 시 원인별 진단 힌트가 제공됩니다.

---

## 8. 우클릭 메뉴

리소스 카드를 우클릭하면 다음 작업을 바로 실행할 수 있습니다.

- **이름 / JSON / YAML 복사** — 클립보드에 복사
- **Pod Logs** — 로그 모달 열기
- **Shell** — `kubectl exec` 명령어를 복사. 터미널에 붙여넣으면 Pod에 접속됩니다.
- **Restart** — Pod 재시작 (그룹이면 확인 팝업)
- **AI Prompt 복사** — 분석용 프롬프트 복사

## FAQ

**토폴로지가 비어있어요** — 네임스페이스를 확인하세요. `⌘.`으로 새로고침해 보세요.

**메트릭이 안 보여요** — metrics-server 설치가 필요합니다. 없어도 토폴로지는 정상 동작합니다.

**YAML 적용이 실패해요** — `kind`, `name`, `namespace` 등 불변 필드는 변경할 수 없습니다. RBAC 권한도 확인하세요.

**Edge가 안 보여요** — Service selector와 Pod label이 일치해야 합니다. ConfigMap/Secret은 Pod에서 참조할 때만 연결됩니다.

**레이아웃이 이상해요** — **Reset layout** 또는 노드 선택 후 `Delete`로 초기화할 수 있습니다.
